# ADR 010: 스냅샷 히스토리는 dev server 메모리에 `@preview` 파일 저장본만 보관한다

- 상태: 채택, `snapshots` 옵션은 `0.x` 동안 실험 단계
- 날짜: 2026-10-18

## 맥락

컴포넌트를 고치다 보면 "아까 버전과 지금 버전이 어떻게 달라졌는지" 보고 싶다. git commit이나
stash 없이, 에디터에서 저장한 그대로의 옛 버전을 지금 버전 옆에 그려 볼 수 있어야 한다.

스파이크(`spike/snapshot-history`, 로컬)에서 plugin이 옛 source를 메모리에 두고 별도 모듈 id로
서빙하면 같은 Provider 안에서 옛 버전과 지금 버전을 나란히 그릴 수 있음을 확인했다. 지금 버전의
HMR과 Fast Refresh도 그대로 동작했다.

## 결정

- 기록 대상: `@preview`가 있는 파일. 저장할 때마다, scanner가 파싱에 성공했고 내용이 바뀐 경우만
  기록한다. dev server가 켜질 때의 내용이 Snapshot 1이다. 서버가 켜진 뒤 `@preview`가 생긴
  파일은 그때가 Snapshot 1이다.
- 번호: 늘어나기만 한다. 오래된 기록을 지워도 번호는 밀리지 않는다.
- 상한: 파일마다 Snapshot 1과 최근 기록을 합쳐 기본 20개. 중간 기록은 지우고 몇 개를 지웠는지
  보여준다.
- 생명주기: 파일을 지우거나 `@preview`를 모두 지우면 기록을 버린다. 다시 생기면 새 기록이다.
  이름 변경은 추적하지 않는다.
- 저장소: dev server 메모리. git, 디스크, 서버 재시작 너머는 다루지 않는다.
- 서빙: `/<file>?vitrine-snapshot=N` 모듈 id로 옛 source를 돌려주고, 사용자의 Vite가 지금 파일과
  같은 방식으로 변환한다. 옛 버전이 import하는 다른 파일은 지금 버전이 쓰인다.
- 렌더링: frame의 격자 칸이 `snapshot` 번호를 가지면 그 버전 모듈을 불러온다. 옛 버전에 같은
  export가 없거나 import한 파일이 바뀌어 깨지면 그 칸에만 안내나 에러를 보여준다.
- 옵션: 자동 저장 에디터처럼 저장이 잦은 환경을 위해 상한과 기록 조건을 바꿀 수 있다. 사용자
  함수는 Node에서만 실행한다([ADR 007](./007-preview-frame.md)).

  ```ts
  vitrine({
    snapshots: {
      limit: 30,
      shouldRecord: ({ lastRecordedAt, now }) => lastRecordedAt === null || now - lastRecordedAt > 3000,
    },
  });
  ```

  `snapshots: false`로 끌 수 있다.

## 결과

- 저장만 하면 옛 버전을 지금 버전 옆에 비교할 수 있다.
- 서버를 다시 켜면 기록이 사라진다. 화면과 문서에 이 범위를 밝힌다.
- 옛 버전은 다른 파일의 지금 버전과 함께 그려지므로, 여러 파일을 함께 고친 경우 그때의 화면과
  다를 수 있다.

## 재검토 조건

- 서버 재시작 뒤에도 기록을 남기길 원하는 요구가 많음
- 여러 파일을 함께 바꾼 시점을 비교하는 요구가 많음
